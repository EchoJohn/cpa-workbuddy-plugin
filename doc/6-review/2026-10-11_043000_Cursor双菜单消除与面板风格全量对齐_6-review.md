## 问题根因与消除措施

### 1. 为什么菜单会有 2 个
- **根因分析**：
  在 `cursor/internal/plugin/management.go` 的 `managementRegistration()` 函数中，此前在 `Resources` 数组中同时声明了：
  ```go
  Resources: []managementResource{
      {Path: "/panel", Menu: "Cursor", ...},
      {Path: "/status", Menu: "Cursor", ...},
  }
  ```
  CLIProxyAPI 宿主在启动和加载插件时，会遍历各插件导出的 `Resources` 列表；凡是具有非空 `Menu` 属性的资源项，宿主均会向左侧导航栏追加一个菜单条目。由于原实现为兼容 `/status` 别名而同时将两个资源都打上了 `Menu: "Cursor"` 标签，导致左侧菜单栏重复渲染出两个并列的 "Cursor" 菜单项。
- **消除措施**：
  修改 `managementRegistration()`，将 `Resources` 收敛为仅声明 `/panel` 作为唯一菜单入口：
  ```go
  Resources: []managementResource{
      {
          Path:        "/panel",
          Menu:        "Cursor",
          Description: "Cursor dashboard: status, usage, token import and model controls...",
      },
  }
  ```
  同时，保持后端 `Routes` 与 `handleManagement` 依然分发支持 `/status` 与 `/accounts`，做到功能与路由兼容性零丢失。更新 `handler_registration_test.go` 单测，断言侧边栏资源唯一性。

### 2. 面板和 workbuddy 风格完全不同
- **根因分析**：
  Cursor 插件原有 `assets/management.html` 系旧版独立移植代码，缺少 CPA 管理面板统一设计规范：
  - 未使用统一的 `--bg:#faf9f5`、`--card:#ffffff`、`--acc:#4c8dff`、`--ok:#10b981` 等 CSS 主题变量体系；
  - 缺乏全屏自适应宽度的 `.wrap{max-width:1400px;margin:0 auto;padding:24px 20px}` 布局；
  - 缺乏现代操作栏 `.bar`（导入 Token、导出凭证、全部启用、全部禁用、搜索、排序）；
  - 缺乏多维状态筛选标签栏 `.filter-bar`（全部、可用、禁用、异常）与 `.summary` 统计概览卡片；
  - 缺少卡片网格 `.grid` 和带有状态 Badge、UID、调用统计、模型标签列表及操作按钮的 `.card`；
  - 缺少统一的 Token 批量导入 Modal、选模型测试探活 Modal、删除确认 Modal 与 Toast 滑入式通知系统。
- **改造对齐措施**：
  将 `cursor/internal/plugin/assets/management.html` 彻底重构，全量采用与 `workbuddy/panel.html` 及 `zcode/panel.html` 完全一致的现代化设计系统：
  1. **主题自适应**：支持默认纸质浅色、`white` 纯白、`dark` 深色，并通过 `__cursorThemeSync` 自动与宿主 iframe 同步；
  2. **统一头部与控制栏**：包含统一标题、副标题、认证密钥输入盒、导入 Token、导出凭证、全部启用、全部禁用、实时搜索与排序按钮；
  3. **指标统计概览**：动态计算并展示总账号数、可用账号数、已禁用账号数及覆盖模型总数；
  4. **账号卡片网格**：响应式 3 列卡片布局，清晰呈现账号标识、UID、累计请求成功/失败数、支持的核心模型标签、选模型实时测试按钮、启用/禁用开关及右上角红叉删除；
  5. **弹窗与通知体系**：提供多行 Token 导入与 JSON 备份一键恢复、选模型实时探活、二次删除确认以及平滑滑入的 Toast 状态提醒。
