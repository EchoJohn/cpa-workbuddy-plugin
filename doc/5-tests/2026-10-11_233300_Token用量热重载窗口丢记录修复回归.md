## 3. 变异反证（证明覆盖真实）

在临时 shim 副本上还原生产修复，不改动仓库文件：

| 变异 | 结果 |
|---|---|
| `errors.Is(err, usagestats.ErrStoreClosed)` → 永不命中 | `--- FAIL: TestIngestFeedChunkStopsOffsetOnClosedStore: closed-store consumed = 1272, want 0`；`--- FAIL: TestIngestFeedChunkResumesAfterReopen: closed consumed = 1284, want 0` |
| `if unchanged {` → `if unchanged && false {` | `--- FAIL: TestReopenStoreKeepsHandleWhenConfigUnchanged: unchanged config must not swap the store handle` |

第一轮变异曾采用"整段删除 `if errors.Is(...)` 分支"，导致 `errors` 导入未使用而 `[build failed]`，属编译期假信号而非语义失败，已改用"永不命中"的等价语义变异重做。

`1272 / 1284` 这两次数字同时给出了生产缺陷的量级解释：一次换句柄窗口约跳过 3 条记录（≈1.3KB feed 行），与实测"每次 reload 掉 7–14 条"同源。
