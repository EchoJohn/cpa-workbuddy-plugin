# 八大插件全景架构与演进计划总览（Gemini 插件已废弃下线）

结论：本项目生态收敛为涵盖 7 大 AI 服务商 Provider + 1 统一用量统计服务的八大插件全景生态（workbuddy、workbuddy-ai、traework、qoderwork、qoder-ai、cursor、zcode、workbuddy-token-usage）。原 gemini-provider 经评估因体积臃肿翻倍、依赖复杂 GCP 绑定且使用门槛极高，已彻底废弃下线并移除全部代码与 Release 资产；全部保留插件代码与单测均已在本地验证通过（cgo-shim 零错误）；本计划全面对齐最新架构事实，废除基于历史旧代码的陈旧假设（如保号池、硬编码模型、旧单模型探活等），确立全插件统一的调度容灾、多模型探活、用量上报与现代控制台规范，并规划后续稳妥演进路径。

## 二、 全仓库统一的五大核心技术规范（防偏差基线）

1. **统一账号调度与容灾规范（绝对废除保号池）**：
   - 历史上的 `preserve` 保号池已被**彻底废除并从全部代码与面板中移除**；
   - 账号过滤契约：`scheduler.pick` 仅让可用账号承载流量——「测试失败」`test_failed` 与「冷却中」`cooling_down` 两类账号**无条件硬排除且无任何回退**；
   - 全灭降级契约：当某插件所有候选账号均不可用时，必须返回 `Handled: false`（全灭 defer），将调度权交还 CPA 宿主进行跨 Provider 故障转移，禁止死锁在故障账号上；
   - 排序契约：存活可用账号一律按剩余可用积分**升序排序**（未测积分 -1 排在最后），优先用完即将耗尽的账号；面板选中项一律同步该口径。
2. **统一自动探活与测试标签规范**：
   - 后台 Watchdog / Refresh Runner 活跃探活：从动态模型中去重抽取最多 5 个模型随机打乱依次探测；
   - 单次请求超时放宽至 20s，整轮叠加 30s 预算截止熔断；
   - 采用 **any-success** 快速判定：任意一个模型成功即判定账号健康，立即清除既有 `test_failed` 标签并终止循环；仅当全部候选模型均失败且账号仍有剩余积分时，才打上 `test_failed` 标签；
   - 面板卡片手动点击「测试」按钮统一弹出模型点选模态框，支持指定单一模型针对性测试。
3. **统一凭据物理落盘规范**：
   - 宿主 `host.auth.save` 序列化时会丢弃未声明的未知顶层字段（如 `test_failed`, `disabled`, `manual_disable` 等）；
   - 所有插件的账号修改（启停、打标、清标、删除）一律采用 `persistAuthDirect` 直写 `~/.antigravity_cockpit/<plugin>_accounts/` 物理 JSON 文件，由文件监听器自动同步到内存镜像，确保状态永不丢失。
4. **统一跨插件用量数据通道**：
   - 所有 Provider 插件在完成流式或非流式推理后，统一将用量元数据（`timestamp`, `provider`, `model`, `auth_id`, `tokens` 等）异步追加至 `<CLIProxyAPI root>/data/token-usage-feed.ndjson`；
   - 统一由 `workbuddy-token-usage` 插件单向消费该文件，彻底避免跨插件共享数据库的文件锁冲突；
   - 供应商标识归一化：支持对 WorkBuddy、QoderWork、Qoder AI、Trae、Gemini、Cursor、ZCode 进行全平台统一聚合。
5. **统一控制台 UI/UX 体验规范**：
   - 面板统一对齐深浅主题自适应、操作栏工具集、模糊搜索、卡片网格、一键全启全停、模型选择测试弹窗与 JSON 备份导入恢复。
